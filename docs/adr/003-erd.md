# ADR 003: ERD 내용

- 상태: 최종 ERD 기준. API와 맞춰야 하는 항목은 아래에 별도로 기록한다.
- 관련 문서: [PRD](../PRD.md), [API 계약](../api-contract.md), [DB 및 스키마 관리](001-database-management.md)

## 배경

유아는 장소에 맞춰 AI가 추천한 놀이를 진행한다. 초등학생은 준비된 문제에 답하고 결과를 확인한다. 초등학생의 답변 이력은 이후 출제에서 이미 답한 문제를 제외하는 데 사용한다.

## 저장 범위

- 유아 추천 API는 요청받은 장소명과 질문 텍스트, 문항별 SVG 이미지 URL을 반환한다. AI 콘텐츠는 DB에 저장하지 않는다. 세 번째 **찾았어요** 선택 후 마침 화면으로 이동하는 흐름은 화면에서 처리한다.
- 초등학생의 놀이, 문제와 보기, 회차별 출제 순서와 답변을 DB에 저장한다. 회원가입 없이 고정 사용자 ID `1`을 사용한다. `activity.auth_id`가 참조할 수 있도록 `auth`에 ID `1`을 초기 데이터로 준비한다.

## 테이블과 관계

| 테이블 | 저장하는 내용 |
| --- | --- |
| `auth` | 고정 사용자 ID |
| `topic` | 놀이 이름과 설명, 놀이 규칙(`rules`), 안내 예시(`example`) |
| `question` | 놀이에 속한 문제 내용과 정답 표시 문구 |
| `choice` | 문제별 보기 순서, 보기 내용, 정답 여부, 해당 보기를 골랐을 때의 피드백 |
| `activity` | 사용자와 선택한 놀이, 나이, 진행 상태, 현재 문제 번호, 전체 문제 수 |
| `activity_question` | 회차에 배정된 문제와 출제 순서 |
| `answer` | 회차에 배정된 문제에서 고른 보기와 채점 결과 |

- `topic → question → choice`로 놀이와 문제 콘텐츠를 연결한다.
- `activity → activity_question → answer`로 회차별 출제와 답변을 연결한다. 푼 문제 수, 맞힌 문제 수, 문항별 복습 내용은 이 관계를 통해 조회한다.

## 중복 방지

- 놀이 시작 시 고정 사용자 ID `1`이 이미 답한 문제를 조회하고, 정답 여부와 관계없이 해당 문제를 출제 후보에서 제외한다.
- 답변 제출 시 회차에 출제된 문제인지, 고른 보기가 해당 문제에 속하는지, 해당 출제 건에 답변이 이미 있는지 서비스 코드에서 확인한다.
- 동시 제출에도 같은 출제 건에 답변이 한 번만 저장되도록 서비스 트랜잭션에서 `activity` 행의 쓰기 잠금을 먼저 획득하고 중복 확인과 저장을 직렬화한다. 이 규칙을 위한 DB 유일 제약은 추가하지 않는다. 다른 저장 경로를 추가할 때도 같은 잠금 규칙을 적용해야 한다.
- 유효한 재제출은 최초 저장한 결과를 `200 OK`로 반환하며 선택한 답을 덮어쓰지 않는다.
- `question.correct_answer_text`는 답변 응답의 필수 정답 문구이므로 새 스키마에서 `NOT NULL`로 관리한다.
- 답변 제출에 필요한 기반은 `V2__create_school_answer_tables.sql`로 생성한다. 엔티티는 외래 키 ID를 필드로 매핑하고 DB의 외래 키 제약으로 참조 관계를 검증한다.

## API 계약과 확인할 사항

- 놀이 시작 API가 본문에서 받은 나이(8~10세)를 `activity.age`에 저장한다. 문제별 대상 나이를 표현하는 DB 구조는 확정 후 ERD에 반영한다.
- 놀이 목록 API의 규칙과 예시는 `topic.rules`와 `topic.example`에서 제공한다. 초기 놀이 3종은 Flyway로 등록한다.
